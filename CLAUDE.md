# CLAUDE.md — tickets_project-pdf-ticket

## Описание

Репозиторий содержит HTML-шаблоны билетов для речных прогулок, предназначенные для конвертации в PDF. Шаблоны используются внешним сервисом (бэкендом tickets_project), который подставляет данные заказа и генерирует готовые PDF-билеты через HTML-to-PDF конвертер.

Репозиторий является частью экосистемы **tickets_project** (GitHub-организация: `webmayak`).

## Стек технологий

- **HTML5** — разметка шаблонов билетов
- **CSS** — стилизация (внешний `style.css` для классического дизайна, встроенные `<style>` блоки для современного дизайна)
- **Base64-изображения** — QR-коды, штрих-коды, логотипы и декоративные элементы встроены непосредственно в HTML

Репозиторий не содержит серверного кода, зависимостей, `package.json` или системы сборки.

### Варианты шаблонов

**Классический дизайн (index.html, ticket-1.html)** — для ООО «РИВЕР»:
- Табличная вёрстка с тремя колонками: корешок (левая), основная информация (центр), контроль/QR-код (правая)
- Корешок содержит краткую информацию о прогулке, дату и цену
- Центральная часть: данные организатора, название прогулки, дата/время, данные владельца (ФИО, телефон, email), причал, теплоход, таблица позиций заказа, итоговая сумма
- Правая часть: QR-код для контроля
- Нижняя секция: инструкции и схема проезда
- Использует внешний `style.css`

**Современный дизайн (ticket-2.html)** — для ООО «МосФлот»:
- Двухколоночная вёрстка: левая (23%) — информация об организаторе, правая — детали билета
- Все стили встроены в `<style>` тег
- Содержит: номер электронного билета, ФИО, телефон, email, дата покупки, код, сумма заказа
- Декоративные разделители (base64 PNG)
- Информация о продавце внизу

**Расширенный дизайн (ticket-3.html, ticket-4.html)** — для ООО «МосФлот» с дополнительными элементами:
- Логотип организатора (base64 PNG)
- Конкретные дата/время отправления и причал
- Секция с инструкциями и иконками
- Блок «Как добраться»
- Предупреждение о запрете еды/напитков
- Контактные данные поддержки (teplohod.info)
- **ticket-4.html** отличается от ticket-3.html форматом расписания: диапазон дат («Ежедневно с 23 июня по 18 октября») вместо конкретной даты

## Запуск и настройка

Специальная установка не требуется. Для просмотра шаблонов достаточно открыть HTML-файлы в браузере.

```bash
# Просмотр шаблона в браузере (macOS)
open index.html
open ticket-2.html
```

> **Примечание:** `index.html` использует внешний `style.css`, поэтому для корректного отображения оба файла должны находиться в одной директории. Остальные шаблоны (ticket-2, ticket-3, ticket-4) содержат все стили встроенными и не зависят от внешних файлов.

## Генерация PDF

Репозиторий сам по себе не генерирует PDF. Шаблоны предназначены для использования внешним HTML-to-PDF конвертером (например, wkhtmltopdf, Puppeteer, или аналогичным инструментом на стороне бэкенда tickets_project).

Процесс генерации билета:
1. Бэкенд получает данные заказа (информация о прогулке, покупателе, позиции заказа)
2. Данные подставляются в соответствующий HTML-шаблон
3. HTML конвертируется в PDF
4. PDF отправляется покупателю (email, личный кабинет)

### Особенности вёрстки для PDF

- Табличная вёрстка (вместо flexbox/grid) для максимальной совместимости с HTML-to-PDF конвертерами
- Все изображения встроены в base64 — не требуются внешние ресурсы при конвертации
- Шрифты: Helvetica, Arial, sans-serif — стандартные системные шрифты
- Фиксированные размеры и отступы через inline-стили

## API / Интерфейс

Репозиторий не предоставляет собственного API. Шаблоны используются как статические файлы, в которые бэкенд подставляет данные перед конвертацией в PDF.

Предполагаемый интерфейс взаимодействия:
- Бэкенд выбирает шаблон на основе типа организатора или настроек
- Placeholder-значения в HTML заменяются реальными данными заказа
- Готовый HTML передаётся в PDF-конвертер

## Сборка и деплой

Система сборки отсутствует. Шаблоны используются как есть.

Для обновления шаблонов:
1. Внести изменения в HTML/CSS
2. Проверить отображение в браузере
3. Проверить корректность конвертации в PDF (через используемый конвертер)
4. Закоммитить и запушить в `main`
